# Cleanup, 30 October 2026: unused code, stale comments, faster UI tests

Branch `chore/cleanup-2026-10-30`, from `perf/ultra-wait-60fps` (95ec110b), so the two merge without conflicts: merge that one first.
The owner asked, before sleeping: sweep the app of code that is no longer used, comments and tests that no longer make sense, so the app is
lighter and the tests faster; decisions are mine. No device tests (the owner was asleep); nothing installed.

## How it was found

- **Unused code:** Periphery 3.8 on a clean index (`--generic-project-config`, `--retain-swift-ui-previews --retain-codable-properties`),
  twice: with the tests indexed (what nothing uses) and with the tests left out of the index (what only tests keep alive). Every hit was
  checked with grep before it went; the known false positives stay (below).
- **Stale comments:** every backticked name in a comment checked against the code (`TypeName`, `Type+Extension`, `member`).
- **Test time:** the last Full's result bundle, step by step (`xcresulttool … activities`): where 136.6 summed minutes of UI tests go.

## 2. UI tests: faster, fewer, steadier

### Faster helpers (measured on the Simulator before changing them)

- **The editor's toolbar** (`EditorApp.tapTool`): it was dragged 120 pt at a time, by half the way, for fear of the bar gliding on. Measured:
  at 200–400 pt a second the bar stops exactly where the drag ends (320 of 330 pt; the rest is the touch's slop); at 600 it glides. It is now
  dragged the reach's whole width at 300 pt a second, inside the part of the bar a tool can be touched in (after ‹, before the pinned Delete),
  the same reach `CreatorWorkflow.tool` already used (the times are in section 3).
- **Waits:** 46 predicate waits (`expectation(for:)`, `XCTNSPredicateExpectation`) and 17 `waitForNonExistence` took their first look after a
  second; they now look at once and every 0.1 s (`matches(_:within:)`, `isGone(within:)`). The device, performance and capture suites keep
  XCTest's own waits: on an iPhone a look every 0.1 s held the app's main thread (the Ultra wait measurement of this morning).
- `CreatorWorkflow.tap` looks every 0.1 s for a second instead of sleeping a second.
- **Not changed, measured:** the list swipe of `scroll(to:)` already moves about 516 pt (the list glides past the hold); longer swipes move
  560–840 pt but can carry a row past the top under the navigation bar. Not worth the risk for about a minute summed.

### Fewer: 25 tests that only repeated another

An audit of the 417 UI tests looked for tests whose steps and checks are a subset of another's; each pair was read again before deleting,
and every check the deleted test had that the other didn't was moved into it. Examples: Format on the main bar (covered by the Format walk
of `CreatorWorkflowUITests`), the Onboarding refusal (a subset of the refusal note test), two star transition tests, the Profile empty/full
pair, Prompter's Aa page (Settings covers it). `CueUniverseScreenshotTests` (pictures for the design handoff) runs only when asked
(`CUE_SCREENSHOT_DIR`), like the other capture suites, and FindInspiration's pictures and their sleeps too.

Medium-confidence merges (tests that start the same way and could share a launch: PlaybackRuns' ten launches, the editor's short opening
checks, Adjust and scrubbing) were **not** done tonight: a merged test stops at its first failure and says less. They are listed in the audit
for the owner's call.

### Steadier

- **Script details from the page's menu** failed in both Fulls of the day. The film of tonight's failure shows the ••• menu open and still,
  the tap landing on "Script details" (269, 93 pt), and nothing happening, twice, 1.1 s after Improve had left. The first idea (the menu opened
  while the sheet was still leaving) was wrong. `tapMenuItem(opening:reopening:)` now does what a person does when a menu lets a tap go by:
  it closes the menu with a tap beside it, opens it again and taps the item. **Open finding:** whether the menu can ignore a person's taps on
  an iPhone is not known (seen only on a Simulator under two clones' load); the page's toolbar rebuilds `ScriptPageMenu` whenever the page
  changes, which is a lead, not a proof.
- **Onboarding's first flight:** two `expectation(for:)` were waited by one `waitForExpectations`; the conversion caught the second only and
  the Full failed on the unwaited first. Both are polling waits now (my mistake, found by the Full, fixed).
- **`StoreManagerTests.anExpiredSubscriptionIsFreeAgain`** failed once: StoreKit's test store took more than 5 s to settle the expiry on a
  loaded Mac. The suite waits up to 15 s; it ends as soon as the tier changes, so a quick store costs nothing.
- **Mask on the video in a window:** the timeline is scrubbed at 250 pt a second so a loaded Simulator doesn't glide past the window.
- **UISmoke** named four tests that no longer existed (renamed or removed), so the smoke run silently skipped four flows; fixed, and
  `scripts/check-project.sh` now fails when a test plan names a test that doesn't exist.

## 3. Before and after

Two Fulls on the same Mac, both with the UI tests on 2 Simulator clones: this morning's (`perf/ultra-wait-60fps`, before the cleanup)
and tonight's (this branch). In the suites whose test files weren't touched, the median test took 1.008× as long tonight: the Mac was
as loaded both times, so the differences below are the cleanup's.

| | Before | After |
|---|---|---|

  summed time, ~1,700–1,800 min, adds up tests that run side by side and says little about speed).
- Zero warnings (`scripts/check-warnings.sh`: simulator, device, Release); `scripts/check-project.sh` passes with the new plan check.
